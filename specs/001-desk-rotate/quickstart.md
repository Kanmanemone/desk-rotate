# Quickstart: 데스크톱 자동 로테이터 + 플로팅 상태창

**Feature**: `001-desk-rotate` | 이 문서는 spec.md의 User Story별 인수 시나리오를 실제로 검증하는 수동 절차다. research.md §4에서 정한 대로, OS 가상 데스크톱 연동부는 자동화 테스트 대신 이 절차로 검증한다.

## 전제 조건

- Windows 10 (버전 1903 이상) 또는 Windows 11.
- 가상 데스크톱을 미리 만들어 둘 필요는 없다 — 초기 탐색·설정 과정에서 지정한 범위의 데스크톱이 부족하면 자동으로 생성한다(FR-033). 다만 자동 생성 경로 자체를 검증하려면(시나리오 1의 (b)) 의도적으로 현재보다 큰 범위를 입력하면 된다.
- .NET 8 SDK 설치.

## 빌드 및 실행

```powershell
dotnet build
dotnet run --project src/DeskRotate
```

## 검증 시나리오

각 항목은 spec.md의 해당 User Story/Acceptance Scenario에 대응한다.

### 1. 시작 입력 및 초기 설정 (User Story 1 시나리오 5·8·9, contracts/startup-input-contract.md)

1. 앱을 실행하면 시작 입력 폼이 뜬다. 기본값(범위 1~3, 간격 300초, 목표 사이클 4)이 미리 채워져 있는지 확인 (FR-026).
2. 순회 범위 시작 1~끝 3, 전환 간격 10초, 목표 사이클 2를 입력 → 총 예상 실행 시간이 60초(10초 × 2사이클 × 3데스크톱)로 미리보기에 표시되는지 확인 (FR-013, SC-005).
3. 제출 후, 화면이 짧게 여러 데스크톱을 오가는 것을 관찰(초기 설정 과정, FR-020) → 원래 데스크톱으로 돌아와 회전이 시작되는지 확인.
4. 각 데스크톱에 플로팅 창이 하나씩 생성되어 있는지 Task View로 확인.
5. **(선택, FR-033 검증)** 현재 존재하는 가상 데스크톱 수보다 큰 범위(예: 현재 3개뿐인데 6~8)를 입력해 다시 실행 → 초기 탐색·설정 중 부족한 데스크톱이 자동으로 새로 생성되며(화면이 여러 번 전환됨) 크래시 없이 완료되는지, 이후 순환 전환이 정상적으로 검증되는지(같은 실제 데스크톱에 겹쳐 생성되어 검증이 항상 성공으로 오판되지 않는지) 확인.
6. **(선택, FR-034 검증)** 가상 데스크톱을 4개 만들어 두고 그중 2번째 데스크톱(Task View에서 두 번째 위치)에서 앱을 실행해 범위 3~5를 입력 → 초기 탐색이 먼저 실제 데스크톱 1번을 스스로 찾아낸 뒤 이동하는지(화면이 왼쪽 끝까지 갔다가 다시 오른쪽으로 이동하는 것이 짧게 보일 수 있음), 이미 존재하는 3·4번 데스크톱은 재사용하고 아직 없는 5번만 새로 생성하는지(Task View에서 최종 데스크톱 개수가 5개인지, 6·7·8·9번처럼 불필요하게 늘어나지 않았는지) 확인.

### 2. 자동 전환 및 순환 (User Story 1, FR-001, FR-002)

1. 아무 조작 없이 10초를 기다린다 → 다음 데스크톱으로 자동 전환되는지 확인.
2. 마지막 데스크톱(3번)에 도달할 때까지 기다린 뒤, 한 번 더 전환 → 첫 번째 데스크톱으로 되돌아가는지 확인 (순환, 핑퐁 아님).

### 3. 남은 시간 및 데스크톱별 횟수 표시 (User Story 3, 4)

1. 플로팅 창에서 남은 시간이 매초 줄어드는지 확인.
2. 전환이 몇 차례 일어난 뒤, 데스크톱별 전환 횟수가 실제 전환 횟수와 일치하는지 확인.
3. 종료까지 남은 전체 시간이 전환이 일어날 때마다 갱신되는지 확인.

### 4. 목표 사이클 도달 (FR-015)

1. 목표 사이클(2사이클 = 6회 전환)에 도달할 때까지 기다린다.
2. 더 이상 자동 전환이 일어나지 않고, 플로팅 창은 열린 채로 최종 통계를 계속 보여주는지 확인.

### 5. 종료 확인 절차 (User Story 2, contracts/floating-window-contract.md)

1. 아무 플로팅 창이나 닫기를 시도 → "정말 종료할까요?" 확인 창이 뜨는지 확인.
2. **취소** 선택 → 회전/카운트가 끊기지 않고 계속되는지 확인.
3. 다시 닫기 시도 후 **종료 확정** → 모든 데스크톱의 창이 함께 사라지고 프로세스가 종료되는지 확인.

### 6. 전환 검증 및 재시도 (User Story 2, FR-017~FR-019)

수동으로 실패를 유발하기 어려우므로, 아래 대체 절차로 검증한다:

1. 앱이 자동 전환을 시도하는 순간에 맞춰 사용자가 직접 `Ctrl+Win+→`를 한 번 더 눌러본다(경쟁 상황 유발).
2. 다음 검증 시점에 시스템이 어긋남을 감지해 재시도하거나(짧은 순간 데스크톱이 한 번 더 바뀜), 최종적으로 실제 위치를 기준으로 데스크톱별 카운트가 보정되는지 관찰한다.

### 7. 창 위치 (FR-021)

1. 플로팅 창이 처음에 화면 상단 중앙에 나타나는지 확인.
2. 드래그로 다른 위치로 옮긴 뒤, 그 위치가 세션 동안 유지되는지 확인.
3. 앱을 재시작하면 다시 상단 중앙에 나타나는지 확인.

### 8. 장시간 실행 안정성 (SC-004)

1. 전환 간격을 짧게(예: 수 초) 설정하고 목표 사이클 수를 크게 잡아, 앱을 여러 시간(가능하면 하루 이상) 켜 둔 채 방치한다.
2. 중간중간 플로팅 창이 멈추거나 응답 없음 상태가 되지 않는지, 남은 시간 표시가 계속 갱신되는지 확인한다.
3. 새 인프라나 모니터링 도구 없이 육안 관찰만으로 충분하다 — 이 항목의 목적은 장시간 타이머/루프에서 크래시나 정지가 없는지 확인하는 것뿐이다.

### 9. 상세 보기 커스텀 닫기 버튼·사이클 진행·표시 옵션 (FR-029, FR-030, FR-031)

1. 플로팅 창을 클릭해 상세 보기로 전환 → 우측 상단에 작은 커스텀 닫기(×) 버튼이 보이는지, "사이클: N / 목표" 형식의 진행 표시가 보이는지 확인.
2. 상세 보기의 닫기(×) 버튼을 클릭 → 최소 보기를 닫으려 할 때와 동일하게 "정말 종료할까요?" 확인 창이 뜨는지 확인 (FR-029).
3. 시작 입력 폼에서 "초 단위로 표시"를 끄고 시작 → 최소 보기 숫자 뒤에 "초"가 붙지 않는지 확인.
4. 시작 입력 폼에서 "사이클 번호 표시"를 켜고 시작 → 최소 보기가 "[N번째] "로 시작하는지, 두 옵션을 모두 켰을 때 텍스트가 잘리지 않고 창 크기가 자동으로 맞춰지는지 확인 (FR-031).

### 10. 테두리 자석 스냅 (FR-032)

1. 플로팅 창을 화면 가장자리(위/아래/좌/우) 가까이로 천천히 드래그 → 테두리에서 몇 픽셀 이내로 들어오면 창이 테두리에 딱 달라붙는지 확인.
2. 붙은 상태에서 다시 안쪽으로 드래그해 임계 거리를 벗어나면 자석 효과 없이 자유롭게 이동하는지 확인.
3. 과도하게 멀리서부터 끌려오듯 붙지 않는지(임계 거리가 "거의 닿을 수준"으로 작은지) 확인.

### 11. 일시정지/재개 (FR-035)

1. 플로팅 창을 클릭해 상세 보기로 전환 → 일시정지 버튼이 보이는지 확인.
2. 일시정지 버튼 클릭 → 남은 시간 카운트다운이 멈추고, 버튼 표시가 "재개"로 바뀌는지 확인. 최소 보기로 전환해도 "일시정지" 표시로 바뀌는지 확인.
3. 다른 데스크톱의 플로팅 창을 확인 → 그 창의 상세 보기에도 일시정지 상태가 동일하게 반영되는지 확인(세션은 하나뿐이므로).
4. 재개 버튼 클릭 → 멈췄던 남은 시간부터 카운트다운과 자동 전환이 다시 진행되는지 확인.
5. 목표 사이클에 도달한 뒤에는 일시정지 버튼이 비활성화되는지 확인.

## 자동화된 부분

- `RotationSession`의 순수 로직(회전 순서 계산, 목표 도달 판정, 재시도 횟수 상한, 남은 시간/총 예상 실행 시간 계산, `VerificationOutcome` 판단)은 `tests/DeskRotate.Tests`의 xUnit 단위 테스트로 커버된다 — 이 quickstart는 그 위의 실제 OS 연동 계층을 확인하는 용도다.
