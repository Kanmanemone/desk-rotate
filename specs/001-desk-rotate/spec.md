## Clarifications

### Session 2026-08-11

- Q: 목표 전환 횟수에 도달하면 프로그램이 어떻게 동작해야 하나요? → A: 전환은 멈추지만 플로팅 창은 열린 채로 최종 통계(총 전환 횟수, 데스크톱별 전환 횟수)를 계속 보여주고, 사용자가 직접 닫아야 종료된다.
- Q: 마지막 데스크톱에 도달했을 때 순환 방식을 어떻게 할까요(끝에서 방향을 바꾸는 핑퐁 방식 vs 처음으로 되돌아가는 순환 방식)? → A: 핑퐁 방식은 양 끝 데스크톱(1번, 마지막 번)이 중간 데스크톱보다 절반만 방문되어 "각 데스크톱을 균일하게 반복 순회"한다는 목적에 어긋나므로 채택하지 않는다. 순환(wrap) 방식을 유지하고, 마지막→처음으로 돌아갈 때 필요한 연속 키 입력 사이에 지연을 두어 입력 씹힘 위험을 완화한다(완전히 제거하지는 못함).
- Q: 전환이 실제로 성공했는지 검증하는 기능을 스펙에 포함할까요? → A: (최초 답변은 "포함하지 않음"이었으나, 이후 재검토를 거쳐 포함하는 것으로 확정됨) 데스크톱마다 창을 하나씩 두고, 공식 `IVirtualDesktopManager.IsWindowOnCurrentVirtualDesktop` API로 전환 시도 후 실제로 도달한 데스크톱을 확인하는 검증 기능을 포함한다. 의도한 데스크톱에 도달하지 못했으면 재시도하고, 그래도 안 되면 실제 위치를 기준으로 내부 상태를 보정한다. 비공식 COM 인터페이스나 강제 포커스 트릭(`SetForegroundWindow` 등)은 쓰지 않는다 — 순수 조회 API라 포그라운드 잠금 문제가 없다.
- Q: 창 상태와 무관하게 전환·검증·카운트 동작이 계속 보장되도록 시스템 트레이 상주 구조를 채택할까요? → A: (최초 답변은 "채택함"이었으나, 이후 재검토를 거쳐 아래 항목으로 대체·확정됨) 트레이 상주 대신, 데스크톱마다 일반 플로팅 창을 두고 사용자가 창을 닫으려 하면 "정말 종료할까요?" 확인을 거치도록 한다. 확인 후 종료를 확정하면 프로그램 전체가 종료된다 — 창이 없으면 정상 동작을 보장할 수 없으므로, 창을 유지하는 것 자체를 확인 절차로 강제하는 방식을 택했다.
- Q: 데스크톱별 창을 hidden 마커 창 대신 일반 플로팅 창으로 바꾸고, 닫을 때 확인 절차를 거치는 방식으로 갈까요? → A: 그렇게 한다. hidden 창과 트레이 상주 대신, 데스크톱마다 사용자 눈에 보이는 플로팅 창(상태 표시와 전환 검증을 겸함)을 두고, 닫으려 하면 확인 창을 띄운다. 확인 후 종료하면 프로그램 전체가 종료되며, 별도의 자동 재생성이나 트레이 메뉴는 필요 없다.
- Q: 프로그램 시작 시 데스크톱 개수만큼 창이 필요한데, 사용자가 이 창들을 직접 각 데스크톱으로 옮겨야 하나요? → A: 아니다. 앱이 시작할 때 각 데스크톱을 자동으로(회전에 쓰는 것과 같은 키 입력 방식으로) 한 번씩 순회하며 방문하는 데스크톱마다 창을 자동으로 생성·배치하고, 끝나면 원래 데스크톱으로 돌아와 평소 회전을 시작한다. 사용자의 수동 개입은 필요 없다. 이 과정에서 화면이 짧게 여러 데스크톱을 오가는 것이 사용자 눈에 보일 수 있다(정상 동작).
- Q: 세션 도중 사용자가 가상 데스크톱의 순서를 바꾸거나 데스크톱을 추가/삭제하면 어떻게 되나요? → A: 시작 시 입력한 개수가 실제와 다른 경우와 동일하게 범위 밖으로 둔다. 기존 검증/재시도/보정(FR-017~019)이 최선의 안전망으로 작동해 극단적으로 어긋나지는 않지만, 순서 변경·추가·삭제에 대한 정교한 재동기화는 보장하지 않는다 — 필요하면 앱을 재시작해 처음부터 다시 설정한다.
- Q: 각 데스크톱의 플로팅 창은 초기에 화면 어디에 위치해야 하나요? → A: 화면 상단 중앙(12시 방향)에 배치한다. 이는 초기 배치일 뿐이며, 이후 사용자는 자유롭게 드래그해서 원하는 위치로 옮길 수 있다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 정해진 간격 자동 강제 전환 (Priority: P1)

여러 가상 데스크톱을 서로 다른 작업 맥락으로 나눠 쓰는 사용자가 앱을 실행할 때 전환 간격, 현재 떠 있는 데스크톱 개수, 총 전환 횟수를 입력하면, 앱은 그 간격마다 목표 횟수에 도달할 때까지 자동으로 다음 가상 데스크톱으로 전환해준다. 사용자는 전환 시점을 스스로 기억하거나 직접 조작할 필요가 없다.

**Why this priority**: decision.md에서 확인된 이 기능의 핵심 동기(포모도로식 집중력 강제 전환)를 직접 충족하는 부분이며, 이것 없이는 나머지 기능(남은 시간/횟수 표시)이 의미가 없다.

**Independent Test**: 앱을 실행하고 아무 조작도 하지 않은 채로 설정된 간격이 지나가는 것을 관찰 — 가상 데스크톱이 자동으로 전환되면 성공.

**Acceptance Scenarios**:

1. **Given** 앱이 실행 중이고 현재 데스크톱 1번에 있음, **When** 설정된 간격이 경과함, **Then** 데스크톱 2번으로 자동 전환된다.
2. **Given** 앱이 마지막 데스크톱에 있음, **When** 설정된 간격이 경과함, **Then** 첫 번째 데스크톱으로 되돌아가 순환한다.
3. **Given** 사용자가 플로팅 창을 닫아 종료를 확정함, **When** 이 동작이 수행됨, **Then** 더 이상 자동 전환이 일어나지 않는다.
4. **Given** 누적 전환 횟수가 사용자가 입력한 총 전환 횟수에 도달함, **When** 다음 간격이 되어도, **Then** 더 이상 자동 전환이 일어나지 않고, 플로팅 창은 열린 채로 최종 통계를 계속 보여준다.
5. **Given** 사용자가 방금 앱을 실행함, **When** 앱이 시작 입력을 받아 초기 설정을 진행함, **Then** 사용자의 추가 조작 없이 각 데스크톱에 플로팅 창이 자동으로 하나씩 생성·배치되고, 원래 있던 데스크톱으로 돌아온 뒤 평소 회전이 시작된다.

### User Story 2 - 실수로 인한 종료 방지와 신뢰할 수 있는 전환 검증 (Priority: P1)

사용자는 플로팅 창을 실수로 닫아 프로그램이 갑자기 멈추는 일을 원하지 않는다. 창을 닫으려 하면 확인을 한 번 거치게 하고, 정말 끄기로 확정했을 때만 프로그램이 종료되기를 원한다. 또한 프로그램이 실제로 의도한 데스크톱으로 전환됐는지 스스로 확인하고, 실패하면 재시도해주기를 원한다.

**Why this priority**: 사용자가 명시적으로 지적한 핵심 우려("제대로 작동하지 않으면 거슬리기만 하는 프로그램이 된다")를 직접 해결하는 부분이며, 이것 없이는 User Story 1이 보여주는 "자동 전환"의 신뢰성 자체가 흔들린다.

**Independent Test**: 플로팅 창을 닫아보고 확인 창이 뜨는지, 취소하면 계속 동작하는지 확인. 전환 실패를 유발해보고(테스트 환경에서) 재시도가 일어나는지 확인.

**Acceptance Scenarios**:

1. **Given** 플로팅 창이 열려 있음, **When** 사용자가 닫기를 시도함, **Then** "정말 종료할까요?" 확인 창이 뜬다.
2. **Given** 확인 창이 떠 있음, **When** 사용자가 취소를 선택함, **Then** 플로팅 창은 닫히지 않고 전환·검증·카운트는 계속 정상 동작한다.
3. **Given** 확인 창이 떠 있음, **When** 사용자가 종료를 확정함, **Then** 프로그램 전체(모든 데스크톱의 창, 전환, 검증 포함)가 종료된다.
4. **Given** 전환을 시도함, **When** 검증 결과 의도한 데스크톱에 도달하지 못했음이 확인됨, **Then** 시스템은 키 입력을 재시도한다.
5. **Given** 재시도 한도까지 시도해도 의도한 데스크톱에 도달하지 못함, **When** 재시도가 모두 소진됨, **Then** 시스템은 실제로 확인된 데스크톱을 새 기준으로 삼아 내부 상태(현재 위치, 전환 횟수)를 보정한다.

### User Story 3 - 남은 시간 및 총 예상 실행 시간 확인 (Priority: P1)

사용자는 작업 중 언제든 화면 위에 항상 떠 있는 작은 플로팅 창을 통해 다음 자동 전환까지 남은 시간을 즉시 확인할 수 있다. 또한 앱 시작 시 입력한 전환 간격과 총 전환 횟수를 곱해 계산한 "총 예상 실행 시간"을 보고, 프로그램이 전체적으로 얼마 동안 작동할지 미리 파악할 수 있다.

**Why this priority**: decision.md의 문제 정의("남은 시간에 대한 가시성 부재")를 직접 해결하며, User Story 1의 자동 전환과 짝을 이루는 최소 기능이다. 총 예상 실행 시간은 사용자가 명시적으로 요청한 항목으로, 시작 전에 전체 계획(언제 끝나는지)을 세울 수 있게 해준다.

**Independent Test**: 앱 실행 후 다른 창으로 작업하면서 플로팅 창만 보고 남은 시간이 줄어드는 것을 확인 — 실제 전환 시점과 표시된 "0"이 일치하면 성공. 별도로, 시작 직후 표시되는 총 예상 실행 시간이 (입력한 전환 간격 × 입력한 총 전환 횟수)와 일치하는지 계산기로 검증.

**Acceptance Scenarios**:

1. **Given** 앱이 실행 중, **When** 사용자가 다른 창(전체화면 포함 여부는 Assumptions 참고)을 사용 중, **Then** 플로팅 창에 남은 시간이 계속 보인다.
2. **Given** 자동 전환이 방금 일어남, **When** 새 간격이 시작됨, **Then** 남은 시간 표시가 설정된 전체 간격 값으로 리셋된다.
3. **Given** 사용자가 시작 화면에서 전환 간격 10분, 총 전환 횟수 6회를 입력함, **When** 앱이 시작됨, **Then** 총 예상 실행 시간이 60분으로 표시된다.
4. **Given** 앱이 실행 중, **When** 자동 전환이 반복해서 일어남, **Then** 종료까지 남은 전체 시간도 함께 갱신되어 표시된다.
5. **Given** 플로팅 창이 처음 생성됨, **When** 초기 배치가 이루어짐, **Then** 화면 상단 중앙(12시 방향)에 나타난다.
6. **Given** 플로팅 창이 화면 상단 중앙에 있음, **When** 사용자가 창을 드래그함, **Then** 원하는 위치로 자유롭게 옮길 수 있다.

### User Story 4 - 데스크톱별 전환 횟수 확인 (Priority: P2)

사용자는 플로팅 창에서 이번 실행 세션 동안 각 가상 데스크톱으로 몇 번 전환했는지 누적 횟수를 확인할 수 있다.

**Why this priority**: decision.md의 문제 정의("전환 이력에 대한 가시성 부재")를 해결하지만, 앞선 스토리들이 먼저 동작해야 의미가 있는 부가 정보이므로 P2로 둔다.

**Independent Test**: 앱을 실행한 채 여러 번의 자동 전환이 일어나도록 기다린 뒤, 플로팅 창의 데스크톱별 횟수가 실제 자동 전환 횟수와 일치하는지 확인.

**Acceptance Scenarios**:

1. **Given** 앱이 막 시작됨, **When** 아직 전환이 한 번도 없었음, **Then** 모든 데스크톱의 전환 횟수가 0으로 표시된다.
2. **Given** 데스크톱 2번으로 자동 전환이 일어남, **When** 플로팅 창을 확인함, **Then** 데스크톱 2번의 횟수가 1 증가해 표시된다.

### Edge Cases

- 사용자가 앱 실행 중 `Ctrl+Win+←/→` 등으로 직접 데스크톱을 전환하면 어떻게 되는가? → 다음 검증 시점(자동 전환 시도 직후)에 해당 데스크톱 창 조회로 실제 위치가 예상과 다름이 확인되며, 재시도 또는 상태 보정이 적용된다. 다만 두 검증 시점 사이(간격 도중)에 실시간으로 감지하지는 않는다.
- 사용자가 입력한 총 데스크톱 개수가 실제 존재하는 가상 데스크톱 수와 다르면 어떻게 되는가? → 앱은 사용자가 입력한 개수를 그대로 신뢰하며, 실제 개수와의 불일치를 검증하지 않는다(범위 밖, Assumptions 참고).
- 가상 데스크톱이 1개뿐인 상태에서 실행하면 어떻게 되는가? → 순환 전환은 항상 같은 데스크톱으로 "전환"을 시도하는 동작이 되며, 이는 정상 동작으로 간주한다(에러 아님).
- 시뮬레이션한 키 입력이 다른 프로그램(단축키를 가로채는 유틸리티 등)에 의해 무시되면 어떻게 되는가? → 전환 시도 직후 검증되며, 의도한 데스크톱에 도달하지 못했으면 재시도한다(FR-017~FR-019). 재시도 한도 내에 해결되지 않으면 실제 위치를 기준으로 상태를 보정한다.
- 플로팅 창을 닫으려 하면 어떻게 되는가? → "정말 종료할까요?" 확인 창이 뜬다. 취소하면 아무 일도 일어나지 않고 계속 동작한다. 종료를 확정하면 프로그램 전체(다른 데스크톱의 창 포함)가 함께 종료된다.
- 확인 창이 떠 있는 동안에도 전환 타이머는 계속 진행되는가? → 그렇다. 확인 창은 그 창 하나의 닫기 여부만 묻는 것이며, 사용자가 응답하기 전까지 전환·검증·카운트는 평소대로 계속된다(Assumptions 참고).
- 목표 전환 횟수에 도달한 뒤에도 앱을 끄지 않고 계속 두면 어떻게 되는가? → 전환은 멈춘 채 플로팅 창은 열린 상태를 유지하며 최종 통계(총 전환 횟수, 데스크톱별 전환 횟수)만 계속 표시한다. 사용자가 창을 닫고 종료를 확정할 때까지 대기한다.
- 총 전환 횟수를 0 이하로 입력하면 어떻게 되는가? → 유효하지 않은 입력으로 간주해 앱은 시작을 거부하고 1 이상의 값을 다시 입력하도록 요구한다 (Assumptions 참고).
- 마지막 데스크톱에서 처음으로 되돌아가기 위해 연속으로 보낸 여러 키 입력 중 일부가 씹혀 누락되면 어떻게 되는가? → 입력 사이 지연(FR-016)으로 발생 확률을 낮추고, 발생하더라도 전환 직후 검증(FR-017)이 이를 감지해 재시도하거나 상태를 보정한다.
- 재시도 한도까지 다 써도 의도한 데스크톱에 도달하지 못하면 무한정 재시도하는가? → 아니다. 재시도 횟수에는 상한이 있으며, 상한 도달 후에는 실제로 확인된 위치를 새 기준으로 삼아 내부 상태를 보정하고 다음 간격으로 넘어간다(FR-019).
- 데스크톱마다 창이 하나씩 뜨는데, Alt+Tab이나 작업표시줄에서 여러 개로 보이지 않는가? → 일반 창이므로 숨기지 않는다. Windows의 "작업표시줄에 표시할 창" 설정(현재 데스크톱만 / 모든 데스크톱)에 따라 사용자에게는 항상 최대 1개(현재 데스크톱 것)만 보이거나, 데스크톱 개수만큼 보일 수 있다 — 이는 OS 설정에 따른 정상적인 차이로 간주하고 앱이 별도로 감추지 않는다.
- 시작 시 데스크톱마다 창을 배치하는 과정은 사용자가 직접 해야 하는가? → 아니다. 앱이 시작할 때 자동으로 각 데스크톱을 한 번씩 순회하며 창을 생성·배치한다(FR-020). 사용자는 수동으로 창을 옮길 필요가 없으며, 이 과정 중 화면이 짧게 여러 데스크톱을 오가는 것이 보일 수 있다(정상 동작).
- 세션 도중 사용자가 가상 데스크톱의 순서를 바꾸거나 데스크톱을 추가/삭제하면 어떻게 되는가? → 시작 시 입력한 개수 불일치와 마찬가지로 범위 밖이다. 검증/재시도/보정(FR-017~019)이 안전망으로 작동해 아예 방치되지는 않지만, 원래 의도했던 순서를 정교하게 복구하는 것은 보장하지 않는다. 필요하면 앱을 재시작해 처음부터 다시 설정해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 실행 중 정해진 간격마다, 사용자가 입력한 총 전환 횟수에 도달할 때까지 자동으로 다음 가상 데스크톱으로 전환을 시도해야 한다 (사용자의 추가 조작 없이).
- **FR-002**: 시스템은 마지막 데스크톱에서 전환할 때 첫 번째 데스크톱으로 되돌아가 순환해야 한다 (전체 데스크톱을 순서대로 순환하며, 누적 전환 횟수가 총 전환 횟수에 도달할 때까지 반복될 수 있다). 각 데스크톱은 동일한 빈도로 방문되어야 하며(균일 순회), 끝에서 방향을 바꾸는 방식은 사용하지 않는다.
- **FR-003**: 시스템은 사용자가 실행 시 현재 떠 있는 가상 데스크톱의 총 개수를 직접 입력하도록 해야 한다 (OS로부터 실제 개수를 조회하지 않으므로).
- **FR-004**: 시스템은 데스크톱마다 하나씩, 항상 위(always-on-top)로 표시되는 플로팅 창을 제공해야 한다. 이 창들은 일반 창이며 숨겨지지 않는다.
- **FR-005**: 각 플로팅 창은 다음 자동 전환까지 남은 시간과, 프로그램 종료까지 남은 전체 시간을 실시간으로 표시해야 한다.
- **FR-006**: 각 플로팅 창은 현재 실행 세션 동안 각 데스크톱으로 전환된 누적 횟수를 데스크톱별로 표시해야 한다.
- **FR-007**: 시스템은 전환 횟수와 남은 시간 상태를 세션(앱 실행) 범위에서만 유지하며, 앱을 재시작하면 초기화해야 한다.
- **FR-008**: 사용자가 플로팅 창을 닫으려 시도하면, 시스템은 "정말 종료할까요?" 확인을 요청해야 한다.
- **FR-009**: 사용자가 확인 창에서 종료를 확정하면, 시스템은 프로그램 전체(모든 데스크톱의 창, 전환·검증 동작 포함)를 종료해야 한다.
- **FR-010**: 사용자가 확인 창에서 취소를 선택하면, 해당 플로팅 창은 닫히지 않고 계속 열려 있어야 하며 전환·검증·카운트는 중단 없이 계속되어야 한다.
- **FR-011**: 시스템은 앱 실행 시 사용자가 전환 간격을 직접 입력/설정할 수 있어야 한다 (고정 하드코딩 값이 아니라, 매 실행마다 원하는 간격으로 조정 가능해야 한다).
- **FR-012**: 시스템은 Windows 환경에서만 동작하면 되며, 다른 운영체제 지원은 요구되지 않는다.
- **FR-013**: 시스템은 앱 실행 시 사용자가 목표 총 전환 횟수를 직접 입력하도록 해야 한다 (1 이상의 정수만 유효한 값으로 받아들인다).
- **FR-014**: 시스템은 입력된 전환 간격과 목표 총 전환 횟수를 곱해 총 예상 실행 시간을 계산하고, 앱 시작 시 및 실행 중 계속 사용자에게 보여줘야 한다.
- **FR-015**: 시스템은 누적 전환 횟수가 목표 총 전환 횟수에 도달하면 자동 전환을 멈춰야 하며, 이때 플로팅 창을 닫지 않고 열어 둔 채로 최종 통계(총 전환 횟수, 데스크톱별 전환 횟수)를 계속 표시해야 한다.
- **FR-016**: 마지막 데스크톱에서 첫 번째 데스크톱으로 되돌아가기 위해 여러 번의 키 입력을 연속으로 보내야 하는 경우, 시스템은 각 키 입력 사이에 OS의 전환 애니메이션이 끝날 시간을 확보하기 위한 지연을 두어야 한다.
- **FR-017**: 시스템은 자동 전환을 시도한 직후, 공식 API로 데스크톱별 플로팅 창을 조회해 실제로 의도한 데스크톱에 도달했는지 검증해야 한다.
- **FR-018**: 검증 결과 의도한 데스크톱에 도달하지 못한 경우, 시스템은 정해진 한도까지 키 입력을 재시도해 의도한 데스크톱에 도달하도록 해야 한다.
- **FR-019**: 재시도 한도 내에도 의도한 데스크톱에 도달하지 못하면, 시스템은 무한정 재시도하지 않고 검증으로 확인된 실제 데스크톱을 새 기준으로 삼아 내부 상태(현재 위치, 데스크톱별 전환 횟수 집계)를 보정해야 한다.
- **FR-020**: 시스템은 앱 시작 시 사용자의 수동 개입 없이, 각 가상 데스크톱을 순서대로 한 번씩 자동으로 방문하며 데스크톱별 플로팅 창을 생성·배치해야 한다. 이 초기 설정이 끝나면 원래 있던 데스크톱으로 돌아와 평소의 회전 동작을 시작해야 한다.
- **FR-021**: 시스템은 각 플로팅 창을 초기에는 화면 상단 중앙(12시 방향)에 배치해야 한다. 이후 사용자는 자유롭게 드래그하여 원하는 위치로 옮길 수 있어야 한다.

### Key Entities

- **로테이션 세션(Rotation Session)**: 앱이 실행되어 있는 동안의 상태 — 총 데스크톱 개수, 현재(검증으로 확인된) 데스크톱 위치, 전환 간격, 목표 총 전환 횟수, 지금까지 누적된 전환 횟수, 다음 전환까지 남은 시간, 종료까지 남은 전체 시간, 계산된 총 예상 실행 시간, 목표 도달 여부, 마지막 검증 결과와 재시도 횟수를 포함. 앱 종료 시 사라진다.
- **데스크톱별 전환 카운트(Per-Desktop Switch Count)**: 각 가상 데스크톱 번호에 대해 이번 세션에서 그 데스크톱으로 전환된(검증된) 횟수. 로테이션 세션에 속하며 영속화되지 않는다.
- **데스크톱별 플로팅 창(Per-Desktop Floating Window)**: 데스크톱마다 하나씩 존재하는 일반 창. 남은 시간·전체 통계를 표시하는 UI 역할과, 어떤 데스크톱에 속해 있는지로 전환 결과를 검증하는 역할을 겸한다. 숨겨지지 않으며, 닫으려 하면 종료 확인 절차를 거친다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 앱을 실행한 뒤 별도의 수동 조작 없이도 설정된 간격마다 가상 데스크톱이 자동으로 전환되는 것을 확인할 수 있다.
- **SC-002**: 사용자는 작업 중 언제든 플로팅 창을 보는 것만으로 1초 이내에 다음 전환까지 남은 시간을 파악할 수 있다.
- **SC-003**: 사용자는 별도의 기록이나 도구 없이 플로팅 창만으로 이번 세션 동안 각 데스크톱으로 몇 번 전환됐는지 확인할 수 있다.
- **SC-004**: 사용자는 앱을 하루 이상 켜 둔 상태로 별도의 수동 리마인더 없이 반복적으로 사용할 수 있다 (앱이 중간에 멈추거나 응답 없음 상태가 되지 않음).
- **SC-005**: 사용자는 시작 화면에서 입력한 값(전환 간격, 총 전환 횟수)만으로 프로그램이 총 얼마 동안 작동할지 실행 전에 미리 알 수 있다.
- **SC-006**: 사용자는 목표 전환 횟수에 도달한 뒤에도 창을 닫기 전까지 최종 통계를 확인할 수 있다 (통계가 갑자기 사라지지 않음).
- **SC-007**: 사용자는 플로팅 창을 실수로 닫으려 해도 확인 절차 덕분에 의도치 않게 프로그램이 꺼지지 않는다는 것을 확인할 수 있다 (질적 지표: 닫기 시도 시 확인 창이 항상 뜨고, 취소하면 동작이 끊기지 않음).
- **SC-008**: 키 입력이 씹혀 전환이 실패하는 상황에서도, 시스템은 검증과 재시도를 통해 대부분의 경우 의도한 순서를 회복한다 (질적 지표: 재시도 한도 내 회복 여부를 관찰로 확인).

## Assumptions

- 회전 대상 범위는 앱 실행 시 사용자가 입력한 "총 데스크톱 개수" 전체이며, 사용자가 지정한 일부만 순환하는 기능은 이번 버전 범위에 포함하지 않는다 (decision.md의 미해결 질문 중 하나를 이 기본값으로 해소).
- 총 데스크톱 개수는 사용자가 앱 실행 시 간단한 입력(시작 입력 창)으로 직접 지정하며, 앱은 이 값을 검증 없이 신뢰한다. 세션 도중 데스크톱의 순서가 바뀌거나 개수가 추가/삭제되는 경우도 같은 이유로 범위 밖이며, 재동기화는 보장하지 않는다(검증/재시도/보정이 안전망 역할만 한다).
- 데스크톱별 플로팅 창은 앱 시작 시 자동으로 각 데스크톱을 한 번씩 순회하며 생성·배치된다(FR-020) — 사용자가 수동으로 창을 옮길 필요는 없다.
- 앱은 실제 전환 결과를 확인할 때 공식적으로 문서화된 `IVirtualDesktopManager` 조회 API(데스크톱별 플로팅 창 기반)만 사용하며, 비공식·비문서화된 내부 COM 인터페이스나 강제 포커스 트릭은 사용하지 않는다 — 조회는 포커스를 빼앗지 않는 순수 읽기 동작이라 포그라운드 잠금 문제가 없다.
- 데스크톱별 플로팅 창은 일반 창이며 숨기지 않는다. Alt+Tab·작업표시줄·Task View에 노출될 수 있으며, 이는 Windows의 "작업표시줄에 표시할 창" 설정에 따라 사용자마다 다르게 보일 수 있다(범위 밖, OS 설정에 맡김).
- "정말 종료할까요?" 확인 창이 떠 있는 동안에도 전환 타이머·검증·카운트는 계속 동작한다 — 확인 창은 그 시점의 닫기 요청 하나만 다루며 나머지 동작을 멈추지 않는다.
- 재시도 한도(몇 번까지 재시도할지)의 정확한 수치는 이 스펙에서 정하지 않고 계획/구현 단계 재량으로 둔다 — 다만 반드시 유한한 상한이 있어야 하며 무한 재시도는 허용하지 않는다(FR-019).
- 플로팅 창은 항상 위(always-on-top)로 표시되며, 초기 위치는 화면 상단 중앙(12시 방향)이고 이후 드래그로 옮길 수 있다(FR-021) — 정확한 스타일/투명도/클릭 통과 여부는 이번 스펙에서 세부 결정하지 않고 구현 재량으로 둔다.
- 사용자가 드래그로 옮긴 창 위치는 세션 범위에서만 유지된다고 가정한다 — 앱을 재시작하면 다시 초기 위치(화면 상단 중앙)로 배치된다(FR-007의 "재시작 시 초기화" 원칙과 일관).
- 이번 버전은 일시정지/재개, 간격 실시간 조정, 시스템 트레이 상주, Windows 자동 시작 기능을 포함하지 않는다 — 창 독립적 동작 보장은 트레이 상주 대신 종료 확인 절차로 대체되었다(이번 clarify 세션에서 최종 결정).
- 전환 횟수와 세션 상태는 앱 재시작 시 초기화되며, 별도 저장소에 영속화하지 않는다.
- 총 전환 횟수는 앱 실행 시 사용자가 매번 직접 입력하는 필수 값(1 이상의 정수)이며, "무제한" 옵션은 이번 버전에서 제공하지 않는다.
- "총 예상 실행 시간"은 전환 간격 × 총 전환 횟수로 계산되는 단순 안내용 값이며, 실제 시스템 타이머 오차 등으로 인한 약간의 편차는 허용 범위로 간주한다.
- 각 데스크톱을 균일한 빈도로 반복 방문하는 것이 목적이므로, 끝에서 방향을 바꾸는 핑퐁 방식은 채택하지 않고 순환(wrap) 방식을 유지한다. 이로 인해 마지막→처음 전환 시점에는 여러 번의 키 입력이 연속으로 필요하며, 입력 사이 지연과 전환 후 검증·재시도를 함께 적용해 위험을 완화한다.
