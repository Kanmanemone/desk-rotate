# UI Contract: 데스크톱별 플로팅 창

**Feature**: `001-desk-rotate` | 관련 요구사항: FR-004~FR-010, FR-015, FR-021~FR-025, FR-035, FR-036, FR-037, spec.md User Story 1~4 Edge Cases

순회 범위 안의 데스크톱마다 하나씩 존재하는, 테두리 없는 플로팅 창의 표시 내용과 상호작용 계약. 창마다 `ViewMode`(Minimal/Detailed)를 독립적으로 가진다.

## 표시 내용 — 최소 보기 (`ViewMode = Minimal`, 기본값)

| 항목 | 갱신 시점 | 관련 요구사항 |
|---|---|---|
| 다음 자동 전환까지 남은 시간(숫자, 표시 옵션에 따라 "초" 접미어·"[N번째] " 접두어 포함 가능) | 매초 갱신, 전환 발생 시 리셋 | FR-023, FR-031 |
| 원형 진행률 그래픽(숫자 오른쪽, 표시 옵션이 켜져 있고 아직 목표에 도달하지 않았을 때만) — 바깥 테두리는 항상 완전한 원형으로 고정, 안쪽은 다음 자동 전환까지 남은 시간 비율만큼만 채워짐 | 매초 갱신, 전환 발생 시 다시 가득 참, 목표 도달 시(`TargetReached`) 그래픽 자체가 사라짐 | FR-036 |

형식: `[ShowCycleNumber ? "[N번째] " : ""] + 숫자 + [ShowSecondsUnit ? "초" : ""]` (예: 둘 다 켜짐이면 "[2번째] 137초", 둘 다 꺼짐이면 "137"). 그 외 정보(총 예상 실행 시간, 종료까지 남은 시간, 데스크톱별 전환 횟수)는 최소 보기에서 보이지 않으며, 닫기 버튼도 없다.

## 표시 내용 — 상세 보기 (`ViewMode = Detailed`)

| 항목 | 갱신 시점 | 관련 요구사항 |
|---|---|---|
| 다음 자동 전환까지 남은 시간 | 매초 갱신, 전환 발생 시 리셋 | FR-005 |
| 프로그램 종료까지 남은 전체 시간 | 매초 갱신 | FR-005, FR-014 |
| 총 예상 실행 시간(고정값) | 세션 내 고정 | FR-014 |
| 현재 진행 중인 사이클 번호 / 목표 사이클 수 | 사이클이 넘어갈 때 갱신 | FR-030 |
| 데스크톱별 누적 전환 횟수 (범위 안 전체 목록, 절대 데스크톱 번호로 표시) | 검증된 전환이 반영될 때마다 갱신 | FR-006 |
| 목표 도달 여부 | `TargetReached == true`가 되면 "완료" 상태로 전환 표시가 멈췄음을 나타냄 | FR-015 |
| 커스텀 닫기(×) 버튼 — 고정 픽셀 크기 대신 실제 렌더링 시점의 글꼴·DPI 기준으로 스스로 크기를 계산 | 상세 보기에서만 표시, 클릭 시 아래 "닫기 상호작용" 절차로 이어짐 | FR-029, FR-037 |
| 일시정지/재개 버튼 — 마찬가지로 고정 크기 대신 렌더링 시점 기준으로 크기 계산 | 상세 보기에서만 표시, 클릭 시 아래 "일시정지 상호작용" 절차로 이어짐 | FR-035, FR-037 |

## 일시정지 상호작용

1. 사용자가 상세 보기의 일시정지 버튼을 클릭 → `RotationSession.IsPaused`를 켠다. 다음 자동 전환까지 남은 시간 카운트다운(FR-005)과 새로운 자동 전환 시도(FR-001)가 멈춘다 — 단, 이미 진행 중이던 검증·재시도 시퀀스(FR-017~019)는 끝까지 마친다. 버튼 표시가 "재개"로 바뀐다.
2. 사용자가 재개 버튼을 클릭 → `IsPaused`를 끈다. 멈췄던 남은 시간부터 카운트다운과 자동 전환이 다시 진행된다.
3. 세션은 앱 전체에 하나뿐이므로, 어느 데스크톱의 창에서 토글하든 다음 화면 갱신(매초) 때 다른 모든 창에도 동일하게 반영된다.
4. `TargetReached == true`(목표 도달, FR-015)이면 버튼을 비활성화한다 — 더 이상 멈출 전환이 없으므로 일시정지가 의미 없다.

## 최소/상세 보기 전환

- 창을 **클릭**(누르고 이동 없이 뗌)하면 `ViewMode`가 토글된다 — Minimal ↔ Detailed (FR-024).
- 마우스를 누른 채 임계값 이상 이동한 뒤 떼면 **드래그**로 간주되어 `ViewMode`는 바뀌지 않고 창 위치만 이동한다 (FR-025).
- 토글은 클릭된 그 창에만 적용된다 — 다른 데스크톱의 창에는 영향 없음.

## 초기 배치

- 창이 처음 생성될 때 화면 상단 중앙(12시 방향)에 테두리 없는 상태로, `ViewMode = Minimal`로 나타난다 (FR-021, FR-023).
- 테두리(제목 표시줄)가 없으므로 창 본문을 마우스로 눌러 드래그해 옮긴다. 옮긴 위치와 `ViewMode`는 세션 동안만 유지되며 앱 재시작 시 다시 초기값(상단 중앙, Minimal)으로 돌아간다.

## 닫기 상호작용

1. 사용자가 창을 닫으려 시도(예: Alt+F4, 상세 보기의 커스텀 닫기 버튼(FR-029), 또는 구현이 제공하는 다른 닫기 수단 — 테두리가 없어 기본 X 버튼은 없다) → "정말 종료할까요?" 확인 다이얼로그를 띄운다 (FR-008). 이 사이에도 `RotationSession`은 계속 갱신된다.
2. 사용자가 **취소** → 다이얼로그를 닫고 창은 그대로 유지, 아무 것도 종료되지 않는다 (FR-010).
3. 사용자가 **종료 확정** → 프로그램 전체(모든 데스크톱의 창, 회전, 검증 로직 포함)를 종료한다 (FR-009). 개별 창 하나만 닫는 동작은 없다 — 종료는 항상 전체 종료다.

## 테두리 자석 스냅

- 드래그 중 창이 소속 화면의 작업 영역 테두리(상/하/좌/우)에서 임계 거리(구현 재량, 작게) 이내로 들어오면 해당 축을 테두리에 맞춰 자동으로 붙인다 (FR-032).
- 임계 거리를 벗어나면 스냅이 해제되고 일반적인 자유 이동으로 돌아간다.
- 과도한 스냅(너무 넓은 임계 거리, 시각적으로 튀는 이동)은 피한다 — "거의 닿을 수준"에서만 작동해야 한다.

## 항상-위 표시

- 모든 플로팅 창은 always-on-top으로 유지된다. 정확한 투명도·클릭 통과 여부는 구현 재량이다.
